# Competition strategy and demo

The goal is a finished, useful creative tool with an honest reproducible workflow. Awards are not guaranteed. The user-provided prize categories guide this plan; verify the current official rules and deadlines before entry.

## Priorities

1. **Grand Prize:** ship a coherent end-to-end experience with a credible live demo, open repository, exported workflows, and real completed renders.
2. **Most Innovative:** demonstrate the seven-direction decision process, preserved settings, branching, comparison, and sequencing. Explain the specific creative benefit. Do not assert that no similar app has ever existed.
3. **Most Viral:** make a seven-way scene transformation easy to understand and remix. Share projects without leaking credentials; do not imply share links embed private rendered media.
4. **Open Weights Only:** the supplied SDXL and LTX graphs avoid partner nodes. Verify model and hosting eligibility under the organizer’s actual definition before claiming this category.
5. **LTX VFX bonus:** use LTX as the core video model, complete real execution, and demonstrate a concrete film/VFX use case. LTX is currently experimental and needs GPU validation.

FLUX API and MiniMax H3 bonuses require their stated core models. The current implementation does not integrate those paths. Adding closed partner API dependencies to the same open-weights workflow may conflict with that category; investigate separate eligible workflows and category rules before expanding scope. Do not weaken the primary experience to collect unsupported badges.

The listed runner-up Comfy credits and model API-credit bonuses are prizes, not evidence of free participation credits. Ask the organizer about starter credits or request a small testing grant; keep a rendering budget.

## Two-minute demo script

**0:00–0:12 — Hook.** Show the same written scene beside seven distinct treatments. “One scene can become seven different films. TAKE7 helps you choose which one to make.” Clearly label any illustrative planning preview.

**0:12–0:32 — Creative input.** Enter a short original scene. Show direction, seed, lens, ratio, and camera text controls. Explain that the seed supports comparison, without promising character identity.

**0:32–0:52 — The idea.** Click Explore seven. Compare two takes and explain the change in emotion, framing, and intent. “We preserve the source scene and make creative alternatives explicit, so each decision is inspectable and reversible.”

**0:52–1:17 — Real output.** Show an actual completed image and an actual LTX video from the configured engine. Display job state and output provenance. A pre-recorded completed render is fine if labeled; do not disguise waiting or substitute a mock for real execution.

**1:17–1:35 — Useful workflow.** Favorite a take, arrange the sequence, export the project and API workflow. Show the workflow in the compatible Comfy environment. Describe sequencing as planning unless a real assembly/export feature exists.

**1:35–1:50 — Remix.** Copy a share link and open it in a fresh browser session. Explain that another creator can inspect the recipe and make another interpretation.

**1:50–2:00 — Evidence and close.** Show the actual public repository, live URL, model list, license notices, and setup guide. “One scene. Seven ways to feel it.”

## Before recording

Complete one image and one LTX render; check media playback and downloads; record the actual runtime and costs; test the public demo in a clean browser; confirm the source repository contains no secrets; and review the category requirements. If LTX is not working, report that limitation and do not present the bonus as qualified.
